# kubeletto — the PaaS platform on the home K3s cluster

Kubeletto (repo `~/Documents/benelabs/kubeletto`) moving home from the rented
server (ADR 0004, deadline 2026-11-05). Plan and cuts:
[design/kubeletto-home.md](../../docs/design/kubeletto-home.md). Inventory,
safety switches and what must never run:
[runbooks/kubeletto-migration.md](../../docs/runbooks/kubeletto-migration.md).

Status: **rehearsal phase 1** — prod's live code in `api` mode on a copy of
the database, reachable only on rehearsal names. Production still serves
every real name from the rented server.

## What is where

| Piece | Where | Source |
| --- | --- | --- |
| Knative Serving + Kourier 1.16.0 | ns `knative-serving`, `kourier-system`, node `k3s` | upstream release YAML + prod's ConfigMaps (`manifests/knative-config.yaml`) |
| Traefik 3.7.1 (chart 40.2.0) | ns `traefik`, ClusterIP only | `traefik-values.yaml` (prod's values + home changes) |
| platform-core, NATS, registry (R2), dockerhub-mirror, routes | ns `platform`, `nats`, `registry`, `traefik` | `manifests/platform.yaml`, generated by `export-from-prod.py` from prod's live objects |
| Redis (replaces Upstash, no persistence) | ns `platform` | `manifests/redis.yaml` |
| Rehearsal route + probe app | ns `traefik`, `rehearsal` | `manifests/rehearsal.yaml` |
| Database | CT 130, db/role `kubeletto` | copy of prod (below) |
| Secrets | k8s Secrets | `secrets.sh`, piped from prod; becomes SOPS at cutover |
| Public names | `home-api.kubeletto.com`, `probe-rehearsal.kubeletto.app` | `network/cloudflare/tunnel.tf` |

Every platform workload carries the control-plane nodeSelector + toleration:
the server node is tainted, and only it passes the Postgres pinhole.

## Converge

```bash
cd services/kubeletto
./export-from-prod.py   # only when prod changed: regenerates manifests/ (read-only on prod)
./secrets.sh            # prod Secrets -> home, with the rehearsal rewrite
./apply.sh              # base, knative, traefik, platform, rehearsal (or one step)
```

The cluster API is not reachable from the LAN side; both scripts go through
root SSH to pve2 and VM 300's guest agent (stdin capped at 1 MiB, hence the
chunked apply).

## The live platform-core image

Prod runs `ghcr.io/podpilott/platform-core:74cd7829`, which exists **only in
prod's containerd** (GHCR answers "not found"; the operator's GHCR token
can't push). It was copied into VM 300's containerd by hand:
`ctr images export` on prod → chunked through the guest agent → `ctr images
import` (sha256 checked). A rebuild of VM 300 loses it; the realigned build
(phase 2) goes to GHCR properly.

## The database copy

`pg_dump` 18 in a throwaway pod on prod (the host has 16, and only prod's IP
passes Aiven's allowlist) → file on the prod host → CT 130 → `pg_restore
--role=kubeletto`. **Aiven delivers ~140 KB/s** (measured with
server-generated data), so the rehearsal copy skips the rows of
`usage_samples` (941 MB, metering the plan drops) and
`openobserve_read_model_exports`; their schema is restored. The cutover copy
needs a plan for this (design §5).

## Restore / rebuild

Stateless except NATS JetStream (`nats-data`, events in flight) and the
dockerhub-mirror cache (rebuildable). The database is CT 130's (dump + PBS).
A rebuild is: VM 300 from `proxmox/opentofu`, then the image copy above, then
Converge.
