# nats — the lab's shared NATS with JetStream

One NATS server for every app's messaging: an account per app, with its own
JetStream limits and its own user; accounts cannot see each other's subjects
or streams. Why: [ADR 0016](../../docs/decisions/0016-shared-nats-and-valkey.md).

## Giving an app an account

1. Add it to `local.nats_accounts` in `proxmox/opentofu/nats.tf` with its
   JetStream limits. A stream's `max_bytes` is **reserved** against
   `max_file` even when the stream is empty, so the limit must cover the sum
   of the app's streams' `max_bytes` (Kubeletto: 12 × 500 MB). The sum over
   all accounts stays under the server's 10 GB (`setup.sh`).
2. `tofu apply`: a password is generated (`random_password.nats["<app>"]`);
   only its bcrypt hash reaches the CT; the server reloads, nobody is cut off.
3. Deliver the password to the app (its own `.tf` or deploy, never in git).

### Connecting

From VLAN 20: `tls://nats.home.arpa:4222`, user = the app's name. The
certificate is self-signed, generated by OpenTofu with the hub's name and IP
(`tofu output -raw nats_tls_cert` in `proxmox/opentofu`): pin it (Go:
`nats.RootCAs(<file>)`). Only a client that cannot load a certificate skips
verification, as Postgres clients use `sslmode=require`.

From outside VLAN 20, an app runs a **leaf node** of its own (stateless,
without JetStream) and gets one exact hEX rule from the leaf's host to 7422.
Its clients connect to the leaf with users the leaf defines (restricted ones
for untrusted clients). A leaf without JetStream does not see the hub's
JetStream by itself; the subject mapping does it, with no client change:

```
leafnodes {
  remotes = [ { url: "tls://<app>:<password>@10.10.20.22:7422", tls: { ca_file: /etc/nats-hub/ca.pem } } ]
}
mappings = { "$JS.API.>": "$JS.hub.API.>" }
```

`ca_file` is the hub's certificate (`nats_tls_cert`); the leaf then verifies
the hub's name or IP like any TLS client (tested 2026-10-14).

Proven 2026-10-14 from VLAN 20, across nodes: a direct client and a leaf
created Kubeletto-sized streams (12 × 500 MB), published with acks and
consumed; then the probe streams were deleted.

## Operations

- **Config test:** `nats-server -c /etc/nats/nats.conf -t` in the CT.
- **Reload accounts:** `tofu apply` re-runs `accounts.sh` (reload, no drop).
- **Upgrade:** bump `NATS_VERSION` + its sha256 (the release's `SHA256SUMS`)
  in `setup.sh`, `tofu apply`: the server restarts, JetStream recovers from
  disk, clients reconnect.
- **Restore:** PBS (the CT); JetStream recovers its file store like after a
  power cut.
